# Changelog

## Unreleased

### Added

- Contracts at `contracts.services.<service>`, each with an `enable` and a required static or dynamic `identity`.
- Claim kinds `binds`, `mounts` and `secrets`, whose mount and secret owners and groups default from the service's identity, and whose secrets hold where their value comes from as the tag `value`, `provided = { }` by default, `generated = { generator; from; }` for a value a generator makes, alone or from the secrets `from` references, or `copied = <reference>` for a copy of one other secret, and leave the rest of their values to the backend, with read-only claim sets at `contracts.claimSets.<kind>.<service>.<id>` and clash checks in `contracts.assertions`. A further check fails when a dynamic identity cannot read its secrets, whether or not a backend is imported, and one when a secret's `value.generated.generator` names a generator no backend adapter provides. A secret's `path` is never null: without a secret backend adapter, reading a `path` or serialising `contracts.claimSets.secrets` fails with an error naming the missing adapter, so import one first.
- `contracts.kinds.mounts.classes`, and the adapter slots `contracts.kinds.secrets.backend`, with the backend's `path` and `generators`, and `contracts.kinds.secrets.delivery`, with the delivered `path`. Each slot is null until its adapter is imported and takes one definition, so a second backend or delivery adapter fails once the slot is read, naming both.
- `lib.mkClaimKind`, for defining further claim kinds from a claim type, a clash rule, a check rule and their own settings under `contracts.kinds.<name>`. The claim type and both rules take named arguments: the kind's `settings` and `resolve`, the configuration's `contracts.resolve`, beside `service` and `identity` for the claim type, `identity` and `claim` for the check rule, and `first` and `second` for the clash rule. None receives the configuration. A check rule returns null, one reason or a list of them, each reported as its own failure. A kind's name may contain only lowercase letters, digits and hyphens, and may not be `enable` or `identity`, the contract's own fields.
- `lib.claimNameOf`, the claim name `<node>_<kind>_<service>_<id>` of the claim a reference names, built from the reference alone without resolving it, and `lib.copiesOf`, a copy of each of a list of referenced secrets, keyed by its claim name with `value.copied` set to its reference, to which a second definition under the same keys adds per-copy fields. Every claim's `name` is built with `claimNameOf`.
- `lib.backendNameOf`, the backend name `<service>_<id>` of a claim, with which a service module names a secret's backend entry, `lib.claimsOf`, the claims of one kind's claim set in a list by service and then id, and `lib.labels.claim` and `lib.labels.reference`, the labels `<service>.<id>` and `<node>:<kind>.<service>.<id>` check messages give a claim and a reference. The shipped adapters name their entries, list their claims and label their messages with them, and use nothing of the library but its public functions and documented options: each receives the public library, `contractsLib`, and the `lint` check fails when one imports an internal helper, naming the file. The shipped claim kinds likewise import nothing and receive what they use. The API reference lists what an adapter uses. An adapter's file under `nixos/adapters` is now a function of the library, not a module, so import an adapter through `nixosModules` or the `nixos` directory, not by its file.
- A secret's read-only `backendPath`, where the secret backend installs it, as the backend slot's `path` answers for its service and id. It equals `path` for an undelivered secret; for a delivered secret, `path` is where its unit reads it and `backendPath` where the backend installed it, so a delivery adapter loads the secret from the claim alone, as the systemd-credentials adapter now does. Reading it without a secret backend adapter fails with an error naming the missing adapter.
- A secret's read-only `generator`, `{ name; sources; }` for a `generated` value, the generator it names and a source for each reference of its `from`, or null for a `provided` or `copied` value, and its read-only `copyOf`, the source of a `copied` value, or null, so a reader tells where a secret's value comes from without reading its tags. The secrets check and the agenix-rekey adapter read them.
- `lib.mkReference`, the reference `mkReference kind { node; service; id; }` to a claim, taking the kind first so a literal never writes `kind`, equal to the `ref` of the claim it names. It fails with a `nixos-contracts:` message naming the reference on a missing or unknown field, and on a node identity, kind name, service name or id that breaks its name rule, with the message the claim constructor gives for that name.
- `contracts.resolveService { node; kind; service; }`, the read-only resolution of every claim of one kind that one service holds on a node, such as all of a backend's binds ([ADR-0012](docs/adr/0012-resolve-a-services-claims-beside-a-reference.md)), returning `{ claims; config; reason; }` with the claims keyed by id as the node's claim set holds them, `{ }` for an enabled contract without claims of the kind, the node's configuration and a null reason, or the reason the service has none, in which case reading `claims` or `config` fails with a message naming the node, kind, service and reason. Its reasons are those of `contracts.resolve` for the names, node and kind, and ``no enabled contract on `<node>` describes service `<service>` `` for a missing or disabled contract; a malformed selection fails as a malformed reference does.
- `lib.mkDefaultContract`, for contracts a node can override field by field, including claims held under `lib.mkIf` or `lib.mkMerge`.
- `lib.types.tag`, which takes the tag declarations of `lib.types.attrTag` and settles definitions that name different tags by priority: the tag whose strongest definition is strongest wins, a definition counting at its strongest leaf, each leaf at its innermost override, and the other tags' definitions are dropped. A false `lib.mkIf` contributes no priority. Two different tags at one priority still fail, naming the option. A contract's `identity` has this type, so a node switches a module's static identity, written through `lib.mkDefaultContract`, to a dynamic one, or a dynamic one to a static one, by writing the other tag at normal priority, and a project's claim kind gets the same switching for its own tags. A secret's `value` has it too, so a node makes a module's generated secret provided by writing `value.provided = { }`, or a copy by writing `value.copied = <reference>`, and a misspelt tag, such as `value.generate`, fails as a type error.
- Checks in `contracts.assertions`, written without the library's prefix, and the read-only `contracts.failures`, the prefixed messages of the failed ones.
- `nixosModules.default`, which forwards the failed checks to NixOS `assertions`, and `modules.generic.default` for any module class.
- Examples for a static-identity service (influxdb2), a dynamic-identity service (alloy) whose secrets a feature module adds, a static-identity service (Grafana) whose secrets are delivered into its unit, a helper daemon with a contract of its own (the chrony exporter) and a project-defined claim kind, evaluated by the checks.
- Adapters `nixosModules.preservation` (mounts into `preservation.preserveAt` by class root), `nixosModules.agenix-rekey` (secrets into `age.secrets` with their owner, group, mode and generator, the rest of a value set on the same entry, the `contracts.kinds.secrets.backend` slot from `age.secrets` and `age.generators`, and a check for a secret without an encrypted file), and `nixosModules.systemd-credentials` (delivered secrets into the `LoadCredential=` of the unit each names).
- References from a secret's value to the secrets it comes from: one in `value.copied`, and a list in `value.generated.from`, which defaults to `[ ]`. A reference names one claim by `{ node; kind; service; id; }` and always names its node, so it means the same claim on every node that reads it, and every claim carries its own as the read-only `ref`, built from the configuration's node identity at `contracts.node`. The read-only `contracts.resolve` finds the claim a reference names, of any kind, in the configuration itself or in the node collection `contracts.nodes`, and returns it with that node's configuration, or the reason it names none. The core resolves each of a secret's references into a source of its `copyOf` or `generator`, `{ reference; reason; }`, the reference as written and a null reason or why the secret cannot read it, with one check per reference for an unknown node, a node without nixos-contracts, an unknown claim kind, a claim of no enabled contract, a referenced secret that is a copy, and a generator's referenced secret that is generated from others itself, and a check for a `contracts.node` missing from a non-empty node collection, all with or without a backend. The agenix-rekey adapter turns the sources into the copy's `rekeyFile` and the generated value's generator `dependencies`, with a check for a referenced node without the adapter. `lib.types.reference`, the type of a reference of any kind, and `lib.types.referenceTo`, of a reference of one kind whose `kind` defaults to it and accepts no other, let a service module's settings carry a reference; `value.copied` and `value.generated.from` take `referenceTo "secrets"`, so a reference of another kind fails as a type error. The library carries nothing between nodes ([ADR-0013](docs/adr/0013-leave-carrying-a-reference-between-nodes-to-the-fleet.md)): a sender's `ref` travels in shared data the fleet chooses, such as nixos-registry, and the receiver writes one secret per reference with `value.copied`, keyed by its claim name, as `lib.copiesOf` does, or one secret `value.generated.from` all of them. Such a copy is an ordinary secret of the receiving service, which every adapter installs from `contracts.claimSets.secrets`. An example shares one token between two nodes through a `let`-bound list of references.

### Changed

- **Breaking:** Claim sets are nested by service and id, as `contracts.claimSets.<kind>.<service>.<id>` ([ADR-0009](docs/adr/0009-name-a-claim-by-node-kind-service-and-id.md)), and every claim holds a read-only `name`, `<node>_<kind>_<service>_<id>`, which no two claims of the node collection share, whatever their kinds. Node identities, kind names and service names may contain only lowercase letters, digits and hyphens, claim ids also `_`, and any other name fails at evaluation, naming it and its allowed characters. The agenix-rekey adapter names each `age.secrets` entry, and the systemd-credentials adapter each credential, `<service>_<id>`, such as `influxdb_admin-token`. Check messages name a claim `<service>.<id>`, such as ``secrets claim `influxdb.admin-token` ``. The secret backend slot's `location` becomes `path`, a function of `{ service, id }`, and the delivery slot's `path` takes `{ unit, service, id }`. The `claimName` module argument and the check that no two claims share a claim name are removed, since no two claims of a node share a service and id.
- **Breaking:** `contracts.node` is required, with no default, and the core's checks read it, so a configuration without a node identity fails to evaluate them with an error naming `contracts.node` ([ADR-0010](docs/adr/0010-require-a-node-identity.md)). A claim's `name` is never null, a reference's `node` is a string, so a reference with a null node fails as a type error where it is written, and resolving a reference no longer gives a reason for a null node.
- **Breaking:** A reference resolves through one function ([ADR-0011](docs/adr/0011-resolve-and-check-a-reference-in-the-core.md)). `contracts.resolve reference` returns `{ claim; config; reason; }`: the claim-set entry, the configuration of the node that holds it and a null reason, or the reason the reference names no claim, in which case reading `claim` or `config` fails with the message `contracts.resolve` raised before. `contracts.lookup` is removed. The agenix-rekey adapter reads a referenced node's entries through the result's `config`.
- **Breaking:** `lib.types.reference` and `lib.types.referenceTo` check each name of a reference against its name rule at definition, so a reference whose node identity, kind name, service name or id breaks it, such as one with the service `web_proxy` in a secret's `value.copied`, fails as a type error where it is written, and `lib.types.referenceTo` of an invalid kind name fails as it is built. `contracts.resolve` fails with a message naming the reference on a value that misses one of `node`, `kind`, `service` and `id` or holds another field, instead of Nix's `attribute 'kind' missing`, and gives a reference with an invalid name a `reason` naming the name and its allowed characters, instead of ``no enabled contract on `<node>` holds it``, so a secret's checks report it as one failed check ([ADR-0011](docs/adr/0011-resolve-and-check-a-reference-in-the-core.md)).
- **Breaking:** A secret names the unit it is delivered to in a writable `unit`, which defaults to a dynamic identity's unit and is null for a static identity, and is `delivered` whenever `unit` is not null, whether or not a delivery adapter is imported ([ADR-0014](docs/adr/0014-name-the-unit-a-secret-is-delivered-to-on-the-secret.md)). A static identity's secret is delivered by naming the unit that reads it, and a dynamic identity's secret is read where the backend installs it with `unit = null`. A delivered secret's `group` defaults to `root`. Checks fail for a delivered secret without a delivery adapter, and for a dynamic identity's secret delivered to a unit other than the identity's. The systemd-credentials adapter delivers into any unit a secret names, and requires `DynamicUser` only for the units of dynamic identities.
- **Breaking:** The tests follow the devnix-labs test standard and run on nix-unit's flake-parts module ([ADR-0015](docs/adr/0015-take-development-tools-from-root-flake-inputs.md)). The root flake gains a `nix-unit` input, which follows `nixpkgs`. The `tests.<system>` output becomes `tests.systems.<system>`, holding the `unit` and `integration` suites. The `evaluation` check becomes `nix-unit`, and the `workflows` check is part of `lint`.
- **Breaking:** A secret's value has three tags ([ADR-0007](docs/adr/0007-say-where-a-secrets-value-comes-from-on-the-secret.md)): `generated = { generator; from; }` replaces both `generated = "<generator>"` and `derived = { generator; from; }`, with `from` defaulting to `[ ]`, so one value has one spelling. The checks on a secret's references follow its references, not its tags: a copy references any secret but a copy, so a copy of a secret generated from others, such as an htpasswd, now resolves and takes its encrypted file, and a generator references only secrets that reference none. A reference that breaks either rule fails with a message naming the rule, and for a copy of a copy the secret to reference instead, such as ``it references `store:secrets.influxdb.copy`, which is a copy of `store:secrets.influxdb.origin`; reference that secret instead.``, in place of `which is copied or derived itself; reference a provided or generated secret`.
- **Breaking:** A secret holds its sources on its copy and its generator ([ADR-0016](docs/adr/0016-hold-a-secrets-sources-on-its-copy-and-its-generator.md)). The read-only `sources` is removed. A copy's source is its read-only `copyOf`, and a generated value's sources are in its `generator`, which becomes `{ name; sources; }` in place of the generator's name. A source is `{ reference; reason; }`, the reference as written and a null reason, or the reason its check reports, in place of the reference's fields with the `claim` it resolves to or a null claim, so it holds no other node's claim and its `reference` passes to `contracts.resolve` as it is. The secrets check reports the reasons of a secret's sources, with the same messages. The agenix-rekey adapter reads `copyOf` and `generator` rather than the value's tags, and resolves each source's `reference`.
- Formatting and lint follow the devnix-labs code quality standard, through [treefmt-nix](https://github.com/numtide/treefmt-nix) ([ADR-0015](docs/adr/0015-take-development-tools-from-root-flake-inputs.md)). The root flake gains a `treefmt-nix` input, which follows `nixpkgs` and which agenix-rekey's own `treefmt-nix` input follows, so the lock holds one copy. `dev/treefmt.nix` replaces the `contracts-fmt` wrapper, `dev/treefmt.toml` and `.prettierrc.json`: `nix fmt` runs nixfmt, deadnix, actionlint and Prettier with its default settings, and no longer runs shfmt, which formatted only `.envrc`. The `treefmt` check replaces `formatting`, and `lint` runs statix and the parent-path rule for adapters and claim kinds; deadnix and actionlint move to `treefmt`. The development shell provides the formatter as `treefmt` instead of `contracts-fmt`.
